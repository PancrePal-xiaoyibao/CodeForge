# Extract Research Framework — 研究方法论反向提取器

**描述**: 从已有的深度研究文档中抽象出可复用的研究框架模板，实现"研究思路模板化、未来场景复用化"。

**核心价值**:
- 不是为了得到特定研究结果，而是提取**研究方法论的元框架**
- 使换时间、换场景做调研时，能复用同样的分析深度和逻辑
- 将隐性研究经验转化为显性方法论模板

---

## 方法论 vs 结论

传统研究流程：
```
调研问题 → 收集信息 → 分析研究 → 输出报告
```

反向提取流程：
```
已有报告 → 识别逻辑 → 提炼框架 → 生成模板 → 复用新场景
```

**核心目标**：
- 提取研究的"元认知框架"（how to think）
- 而非研究的"具体结论"（what to think）
- 实现研究方法论的跨场景迁移

## 研究方法论框架的六个核心维度

### 维度1: 宏观背景分析框架

**识别要素**：
- 历史周期对标（类比哪个历史时期、为什么）
- 时代特征判断（结构特征、趋势、驱动因素）
- 关键时间节点识别（规律性/突发性事件）

**提取模板结构**：
```markdown
## 宏观背景分析框架

### 1. 历史对标分析
- **对标周期**: [历史时期]
- **相似性维度**:
  - [维度1]: 具体相似点
  - [维度2]: 具体相似点
- **差异性警示**: 关键差异点

### 2. 时代特征画像
- **核心特征1**: [特征描述] → 对研究对象的影响
- **特征判断依据**: 数据/事实支撑

### 3. 关键时间窗口
- **时间节点**: [具体时间]
- **事件性质**: [规律性/突发性]
- **战术含义**: 如何利用这个时间点
```

**提取指令**：
```
分析报告的宏观环境章节，识别：
1. 报告如何进行历史周期对标？选取了哪个时期？为什么？
2. 报告如何刻画当前时代特征？从哪些维度分析？
3. 报告识别了哪些关键时间节点？有什么规律？
```

### 维度2: 对象分类框架

**识别要素**：
- 核心分类逻辑（按什么维度分成几类）
- 分类依据（属性、驱动因素、角色）
- 类别之间的关系（互补、替代、对冲、上下游）

**提取模板结构**：
```markdown
## 对象分类框架

### 分类逻辑：[核心分类名称]
- **分类依据**: [按什么维度分类]
- **类别数量**: [共几大类]

### 类别定义与属性

#### 类别1: [名称]
- **核心属性**: [这是什么类型]
- **核心驱动因素**:
  1. [因素1] → [具体影响机制]
- **角色定位**: [主/次/对冲/辅助]
- **与其他类别关系**: [互补/替代/对冲]
```

**提取指令**：
```
分析报告的对象分类逻辑：
1. 报告如何对研究对象进行大类划分？分类依据？
2. 每个类别的核心驱动因素？
3. 不同类别之间如何配合使用？
```

### 维度3: 驱动逻辑验证框架

**识别要素**：
- 必要条件 vs 充分条件
- 逻辑链条的完整性（A→B→C）
- 多重逻辑共振机制（多支柱共同驱动）

**提取模板结构**：
```markdown
## 驱动逻辑框架

### 逻辑支柱1: [逻辑名称]
- **机制描述**: [如何驱动结果]
- **关键指标**:
  - [指标1]: 当前值、趋势、临界点
- **持续性判断**: [持续条件/转折信号]
- **数据来源**: [哪里获取数据]

### 逻辑共振验证
**必要条件清单**（全部满足才有强结果）:
- [ ] 条件1: [具体描述]
- [ ] 条件2: [具体描述]

**转折信号监测**（出现则警惕逻辑失效）:
- [信号1]: [具体描述]
```

**提取指令**：
```
分析报告的驱动逻辑部分：
1. 报告如何论证结果发生/持续的必要性？从哪几个维度？
2. 每个逻辑支柱的关键验证指标？
3. 报告如何判断逻辑的持续性和转折点？
```

### 维度4: 多层验证体系

**识别要素**：
- 宏观/环境层验证（是否符合大趋势）
- 结构层验证（产业链卡位、竞争格局、技术壁垒）
- 微观/健康层验证（财务或性能指标、资源支撑）

**提取模板结构**：
```markdown
## 多层验证体系

### 第一层：环境层验证
**核心问题**: 研究对象是否符合宏观大趋势？
验证清单：
- [ ] 是否受益于[核心趋势]？
- [ ] 驱动因素是否属于[必要逻辑]而非短期题材？
- [ ] 环境是否支持该逻辑持续[时间周期]？
**不合格标准**: [什么情况下淘汰]

### 第二层：结构层验证
**核心问题**: 在结构中是否有确定性位置？
1. 链条卡位 / 议价能力 / 不可替代性
2. 市场份额与壁垒（占有率、技术壁垒、护城河）
3. 竞争格局（集中度、主要对手、相对优势）
**不合格标准**: [什么情况下淘汰]

### 第三层：微观层验证
**核心问题**: 是否有持续的支撑？
硬性指标清单 + 阈值 + 数据来源
**不合格标准**: [什么情况下淘汰]
```

### 维度5: 风险预警与动态调整框架

**识别要素**：
- 风险分级（系统性/结构性/个体性）
- 预警信号（什么信号出现需要行动）
- 动态调整规则（仓位/策略如何随信号变化）

**提取模板结构**：
```markdown
## 风险预警与动态调整框架

### 风险分级
- **系统性风险**: [定义+信号]
- **结构性风险**: [定义+信号]
- **个体性风险**: [定义+信号]

### 预警信号清单
| 信号 | 含义 | 应对动作 |
|------|------|---------|

### 动态调整规则
- 信号A出现 → [调整动作]
- 信号B出现 → [调整动作]
```

### 维度6: 专家观点整合框架

**识别要素**：
- 观点收集（来源、立场、置信度）
- 观点分类（共识/分歧/独见）
- 权重分配（如何综合不同观点）

**提取模板结构**：
```markdown
## 专家观点整合框架

### 观点池
| 来源 | 立场 | 核心观点 | 置信度 | 证据 |
|------|------|---------|--------|------|

### 共识与分歧
- **共识**: [多数一致的观点]
- **分歧**: [争议点 + 各方论据]

### 综合判断
- 权重逻辑: [如何分配权重]
- 结论: [综合后的判断]
- 反方验证: [最强反驳 + 应对]
```

## 研究框架提取工作流程

```
①输入报告 → ②识别逻辑 → ③提取框架 → ④生成模板 → ⑤验证通用性 → ⑥输出交付
```

### 步骤 1: 输入确认
- 确认要分析的深度研究报告
- 确认提取维度（单个或全部六维）
- 确认输出要求

### 步骤 2: 快速阅读
- 通读报告结构（目录、章节标题）
- 标记方法论相关的章节
- 识别研究逻辑主线

### 步骤 3: 逐维度提取
- 按选中维度逐个分析
- 提取"识别要素"中的关键信息
- 生成对应模板

### 步骤 4: 通用化处理
- 去除场景特定内容
- 将具体结论转为变量占位符
- 确保跨场景可复用

### 步骤 5: 验证与交付
- 检查六维度覆盖完整性
- 验证模板可操作性
- 输出研究框架文档

## 研究逻辑流程图

```
输入：深度研究报告（单份或多份）
  │
  ├─ 宏观背景分析（历史对标+时代特征+时间窗口）
  ├─ 对象分类框架（分类逻辑+类别属性+关系）
  ├─ 驱动逻辑验证（逻辑支柱+共振验证+转折信号）
  ├─ 多层验证体系（环境→结构→微观）
  ├─ 风险预警与调整（风险分级+预警信号+动态调整）
  └─ 专家观点整合（观点池+共识分歧+综合判断）
  │
输出：研究方法论框架文档（可复用模板集）
```

```markdown
# [研究主题]研究方法论框架

## 方法论核心画像

- 分析维度: [使用了哪些分析维度]

- 适用边界: [这个框架适用于什么场景]

## 六维度框架
[按提取结果逐维度呈现]

## 研究工作流程
[完整的研究步骤流程]

## 适用场景与限制
- 适用: [什么场景下使用此框架]
- 限制: [什么场景不适用]
- 前提条件: [使用前需要什么准备]
```

## 质量控制标准

**完整性检查**：
- [ ] 是否覆盖了六个核心维度？
- [ ] 每个维度的分析步骤是否清晰？
- [ ] 是否提供了可操作的模板？

**通用性检查**：
- [ ] 模板是否去除了场景特定的内容？
- [ ] 变量是否明确标注？
- [ ] 跨场景复用是否可行？

**可操作性检查**：
- [ ] Agent 是否能直接使用这些模板？
- [ ] 是否提供了使用示例？
- [ ] 是否说明了限制条件？

## 高级功能

### 功能1: 框架对比分析
当有多个研究报告时，对比它们的研究方法论：

```markdown
## 研究方法论对比

| 维度 | 报告A方法 | 报告B方法 | 共性 | 差异 |
|-----|---------|---------|-----|-----|
| 宏观分析 | 历史对标 | 数据驱动 | 都重视宏观 | 方法不同 |
| 验证体系 | 多层验证 | 因子模型 | 都有多层验证 | 维度不同 |

**推荐融合方案**: [如何结合两者优点]
```

### 功能2: 框架迭代建议
基于已有框架提出改进建议：
1. 识别框架的盲点
2. 参考其他研究的优点
3. 提出增强方案（版本2.0：新增维度/优化流程/增强验证）

---

## 注意事项

1. **方法论 vs 结论**: 提取的是研究方法论（how），而非研究结论（what）
2. **通用 vs 定制**: 识别通用方法论 vs 场景特定内容
3. **静态 vs 动态**: 研究框架需要随时间迭代
4. **理论 vs 实践**: 提取的框架需要在实际研究中验证和调整

## 使用建议

### 何时使用
- 完成深度研究后，想要沉淀研究方法论
- 想要复用成功研究的分析逻辑
- 想要为 Agent 系统构建研究 prompt 模板
- 想要对比不同研究的方法论差异

### 如何最大化价值
1. **积累方法论库**: 逐步建立多个领域的研究框架模板
2. **定期迭代**: 根据实际研究效果优化框架设计
3. **团队共享**: 分享给团队统一研究标准
4. **Agent 训练**: 用框架模板训练 AI Agent 提升研究质量
